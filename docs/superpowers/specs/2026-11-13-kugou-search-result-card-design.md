# 酷狗搜歌结果图片卡片设计

日期：2026-11-13
状态：待用户确认；本文仅设计，不授权实现、提交或推送。

## 1. 目标与已确认需求

把 `/酷狗搜歌` 的返回从纯文本列表改为**一张图片卡片**，让结果可读、且能靠封面确认选中的是不是想听的那首。

用户已确认的需求：

- 输出改为图片形式。
- 卡片内每首歌必须显示：**歌名、封面、歌手、专辑**。
- 采用**轻量扁平版**排版（浅色白底、单列行式、分隔线分行的行式列表），不照搬参考项目的深色渐变/毛玻璃外观。

已知的现状问题：`main.py` 的 `_search_flow` 目前用字符串拼接输出 `[酷狗搜索] 「关键词」共找到 N 首歌:` 加若干行「序号. 歌名 - 歌手 [时长] [VIP]」。

## 2. 本设计采用的默认决定

以下是设计者的建议，不是用户额外提出的要求；用户确认本文后实施：

- 一次搜歌只回**一张图**；序号即后续 `/酷狗下载 <序号>` 的序号，顺序与 `search_cache` 中保存的列表一致，渲染不做重排。
- 渲染**完全本地**（Pillow 绘制），不调用 AstrBot 的在线文转图（`context.html_renderer` / `t2i.soulter.top`），不引入浏览器截图。理由是离线可用、延迟稳定，且参考项目已验证这条路可行。
- 封面图**由插件自己下载**后再画进卡片，不把远程 URL 交给渲染方。
- 渲染失败或无法取得可用中文字体时，**回退到现有的纯文本列表**，功能不退化。
- 不新增「图/文」开关；成功搜到结果即出图。失败的提示（用法错误、搜不到、接口报错）仍为文本。
- 不加品牌水印；页脚只保留操作提示与结果来源。
- 新增一项缓存 TTL 配置 `cache_ttl_hours`（默认 **24 小时**），**统一**管理三类落盘内容的留存：音频文件缓存、封面图片缓存、渲染出的卡片图。搜歌候选列表**不在其列**，仍固定 5 分钟。
- 封面与卡片图写入**插件数据目录**（`covers/`、`search_cards/`），音频继续留在共享目录的插件子目录；三者共用同一个 TTL 值但各管各的目录，且都不写入共享音频目录。

## 3. 非目标

不增加：点歌/下载结果出图、歌词、歌单、批量下载、多平台、图片卡片点击跳转、把封面单独作为图片消息发送。

不改动下载链路（`file_cache`、`DownloadLadder`、OneBot 上传）与登录链路（`kugou_login`）。

## 4. 用户交互与视觉规格

### 流程

1. `/酷狗搜歌 <关键词>` → 搜索（沿用现有概念版优先、公共源兜底的逻辑）。
2. 成功且有结果时：并发抓取封面 → 本地渲染 → `event.image_result(卡片路径)`。
3. `debug` 开启时，另发一条文本结果承载 `_flush_debug()` 内容（敏感信息仍按现有脱敏规则处理）。
4. 产出图片前先校验 PNG 可读；若向事件产出图片这一步抛出异常，则改发纯文本列表。正常路径**只发图**，不图、文各发一份。
5. 无结果 / 用法错误 / 接口异常：维持现有文本提示。

### 卡片规格（轻量扁平版）

- 画布宽度固定 **800 px**（宽度不设为配置项）；高度按行数计算，不留空白。
- **页眉**：左侧标题「「<关键词>」搜索结果」，右侧「共 N 首」；底部 1px 分隔线。
- **每行**：序号徽章（24×24、圆角 8、accent 蓝 `#2f86bd` 白字）+ 封面（56×56、圆角 8）+ 文本区 + 右侧时长（`M:SS`）。
- 文本区两行：歌名（15px、加粗、过长省略）、副行「歌手 · 专辑」（12.5px 灰 `#8a9097`、过长省略）；歌手或专辑缺失时副行只显示存在的一项。
- 行间 1px 分隔线 `#f7f8f9`；最后一行下方为**页脚**提示「发送 /酷狗下载 序号 获取歌曲文件」。
- 配色：正文 `#1a1c1e`、次要 `#8a9097`、分隔线 `#f1f2f3`、页脚底 `#fafbfb`。
- VIP 标记：行内以小字标签呈现（沿用现有 `pay_type == 3` 判定）。

具体像素、字号与间距由开发者在小范围内微调；上述为设计基线。

## 5. 封面获取

- 封面地址来自搜索结果的 `trans_param.union_cover`，形如
  `http://imge.kugou.com/stdmusic/{size}/20230920/xxx.jpg`：把 `{size}` 替换为 `240`，并把协议**升级为 `https://`**（已实测 `https://imge.kugou.com/...` 返回 200 / `image/jpeg`）。
- **两种搜索源都带该字段**（已实测）：概念版 `/v2/search/song` 的条目含 `trans_param.union_cover` 与 `AlbumName`；公共 `mobilecdn` 搜索的条目含 `trans_param.union_cover` 与 `album_name`。因此登录与否都能取到封面。
- 抓取约束：
  - 复用 `file_cache.is_safe_url(url, allowed_suffixes=(".kugou.com",))` 做 SSRF 校验（`imge.kugou.com` 已落在默认允许后缀内）。
  - **跟随重定向的策略与 `file_cache.Downloader` 保持一致**：请求使用 `allow_redirects=False`，每一跳都重新过 `is_safe_url`，跳数计入上限（最多 5 跳）。既不能「校验一次就放任跳转」（可被 302 绕过 SSRF 检查），也不能一律拒绝跳转（会把合法的 http→https 跳转全变成占位）。
  - 并发上限 3、每张超时 5 秒、整批超时 8 秒、单张大小上限 8 MiB、像素上限（防解压炸弹）。
  - 不向图片主机转发任何酷狗 Cookie / token。
  - 任一张失败（超时、非 2xx、非图片、超限、坏图、跳转不安全或超跳数）→ 该行用同风格**占位封面**，不使整张卡失败。
  - 全部失败 → 仍渲染卡片（全员占位）。
- 封面 URL 取不到（字段缺失或为空）时直接占位，不额外请求别的接口。
- **封面落盘缓存**：抓到的封面按「规范化后的封面 URL」哈希存到插件数据目录的 `covers/`，命中缓存直接读本地文件，不再重新下载（同一首歌反复搜只抓一次）。缓存文件由 `cache_ttl_hours`（见 §8）统一清理；缓存写入失败（磁盘满、权限）只影响当次渲染，不报错。

## 6. 数据归一化变更

`kugou_client.normalize_songs` 增加两个字段（值缺失时为空串/None）：

- `album`：`AlbumName` / `album_name` / `AlbumSingleName` 取首个非空。
- `cover`：`trans_param.union_cover`（优先），回退 `Image` / `AlbumImage`。
- `trans_param` 的形状：**实测概念版 `gateway.kugou.com/v2/search/song` 与公共源都返回对象**（2026-11-13 实测确认是 dict，非 JSON 字符串）。但因为它被包在 `_search_lite` 里、异常会被 `search()` 吞掉再退到公共源，形状误判会**静默降级**且现有测试抓不到，因此 `normalize_songs` 同时接受 **dict 或可 `json.loads` 成 dict 的字符串**，其它情况按字段缺失处理。

`search` 返回项的既有字段（`hash`、`songname`、`singername`、`duration`、`pay_type` 等）与用途不变；`search_cache` 直接存更丰富的条目，无需迁移，旧缓存条目缺 `album`/`cover` 时按缺失处理。

## 7. 渲染实现约束

- 新增模块 `search_card.py`（与 `audio_probe.py`、`quality.py` 同级），只依赖 Pillow 与标准库，不导入 astrbot（便于离线测试）。
- 对外提供一个异步入口，形如 `async def render_search_card(songs, keyword, output_dir, covers=None, ...) -> str`，内部用 `asyncio.to_thread` 执行同步绘制，避免阻塞事件循环。
- 字体发现顺序：Windows `msyh.ttc`/`msyhbd.ttc`（微软雅黑）→ macOS `PingFang.ttc` → Linux `NotoSansCJK-Regular.ttc` 等候选；此外可回退到 AstrBot 数据目录下的 `font.ttf`。
- **“可用中文字体”的判定要看字形覆盖，而不只是能否加载**：把候选字体渲染「永」的位图，与渲染一个私用区码位（如 `U+E000`，必然缺字）的位图比较；两者一致说明该字体没有中文字形（渲染出来就是豆腐块），换下一个候选。
- 所有候选都不含中文字形 → **不渲染，回退纯文本**（回退的目的正是避免满屏豆腐块，而不是仅仅避免加载失败）。
- 绘制前先算清总高度再开画布，杜绝内容溢出或截断。
- 文本统一做省略/换行约束；歌名最多 2 行。
- 封面读入后等比裁剪到方框并加圆角；损坏/超大封面按占位处理。
- 输出 PNG 到 `output_dir`（插件数据目录 `search_cards/`）；文件名不含关键词与平台非法字符，由 `cache_ttl_hours` 统一清理。
- 内存中的图片对象用后即释放；`Image.open` 的结果必须 `load()` 后关闭句柄。

## 8. 配置

沿用 `search_count`（决定卡片行数上限，1–10）与 `debug`。

新增：

### cache_ttl_hours（缓存保留时长）

- 整数，默认 `24`（小时）；滑块建议 1–720。
- **统一**决定三类落盘内容的保留时长：音频文件缓存、封面图片缓存（`covers/`）、卡片图（`search_cards/`）。
- 现有音频缓存的 TTL 由硬编码的 `CACHE_TTL_SECONDS = 3600` 改为读取本配置；`CacheManager.cleanup()` 已接受 `ttl_seconds` 参数，直接传入即可。
- 新增的 `covers/`、`search_cards/` 用同一数值做有界清理，沿用现有清理规则：只扫自己目录的一级子项、不跟随符号链接/junction、不递归进共享目录其他内容。
- 非法值（非整数、< 1）在 WebUI 明确提示并回落到默认 24；不静默使用异常值，也不因此中断搜歌。
- **搜歌候选列表的 5 分钟窗口不受本项影响**（`SEARCH_TTL_SECONDS` 保持不变），避免长期停留在一次过期列表上。
- 本项只控制留存时长，不改变「下载文件在活跃任务与上传期间不得被清理」的既有保护（`hold`/`release`）。

`requirements.txt` 新增 `Pillow>=9.5.0`。理由：本地渲染的唯一硬依赖；AstrBot 生态已普遍自带（本机实测 12.3.0），版本下限对齐参考项目。若 Pillow 缺失，导入时延迟报错并回退纯文本。

**注意**：既有实施计划（`docs/superpowers/plans/2026-11-13-kugou-lite-file-sending.md`）把「不新增运行期依赖」列为全局约束。本设计**有意覆盖**该约束（Pillow 为新增运行期依赖）；后续计划需显式声明这次覆盖。

## 9. 与既有契约的冲突及文档同步

现有插件多处声明「**不发送音乐卡片、语音、封面图片或播放直链**」。本设计**有意推翻其中的“封面图片”部分**——搜歌结果改为带封面的图片卡片；「只发送音频文件附件」在**下载**环节不变。

需同步修改：

- `metadata.yaml`：`desc` 中该条改为「搜歌返回带封面的图片卡片；下载只发送音频文件附件，不发送音乐卡片、语音或播放直链」。
- `main.py` 模块头注释（第 7 行同义句）。
- `README.md` 中描述搜歌输出与「不发送封面」的段落，以及新增的缓存 TTL 配置说明。
- `_conf_schema.json`：新增 `cache_ttl_hours`（整数，默认 24，含说明与滑块）。
- 版本号从 `2.0.0` 提升为 `2.1.0`（向后兼容的功能新增）。

## 10. 安全

- 封面请求必须过 `is_safe_url`；拒绝 IP 直连、内网/环回/保留地址、URL 内凭据与未知主机（沿用既有 SSRF 规则）。
- 限制单张字节数与像素数，防止解压炸弹与内存放大。
- 不向 `imge.kugou.com` 发送 Cookie/token 或任何账号信息。
- 渲染在后台线程执行，不读用户可控路径；写入目录固定在插件数据目录内。
- 卡片文本来自酷狗返回，按纯文本绘制（Pillow 不解析标记语言），并对超长文本截断，避免渲染异常或超大画布。

## 11. 验证与交付标准

离线测试（mock 网络，不开真实请求）：

- `normalize_songs` 在两种来源下都能取到 `album`/`cover`（含字段缺失、`{size}` 模板替换、`https` 升级）；`trans_param` 为对象和可解析 JSON 字符串两种形状各一条夹具；不可解析时不报错、按缺失处理。
- 封面抓取：安全 URL 通过、越权主机被拒、**302 跳到内网主机被拒**、跳数超限被拒、超时/非 2xx/超大/坏图 → 占位；全部失败仍出图。
- 渲染：固定高度不溢出、行数=结果数、序号正确、缺歌手/专辑/时长时不崩且版面正常。
- 字体路径 → 回退纯文本，且断言覆盖**加载失败**与**加载成功但无中文字形**两种情况，均不产出图片。
- `_search_flow`：成功走 `image_result`；产出图片抛错时改发纯文本列表且不重复发图；无结果/用法错误/接口异常仍走文本；`debug` 开启时附带调试文本。
- 封面缓存：同一封面 URL 第二次搜歌命中本地文件、**不再发起网络请求**；缓存写入失败不影响当次渲染。
- 缓存 TTL：`cache_ttl_hours` 同时作用于音频、封面、卡片三类目录；搜歌候选列表仍固定 5 分钟；非法值（非整数/小于 1）回落默认 24 且不中断搜歌。
- 卡片文件写入 `search_cards/` 且具备 TTL 清理，不触碰共享音频目录。

运行语法检查与离线测试，更新 README、`metadata.yaml` 与版本号。真实图片渲染在本机执行一次并人工核对版面（本机有 Pillow 与中文字体，可覆盖）；封面 URL 的可达性已实测，但**群内实际到达效果以一次真实发送为准**，无真实环境时明确列为待验证。

## 12. 参考与已知限制

- 参考实现：`astrbot_plugin_denia_share`（本地 Pillow 卡片，MIT，派生自 `astrbot_plugin_rika_share`）的 `core/music/search_card.py`；本设计只借鉴其**做法**（本地绘制、封面预下载、`to_thread`、占位降级、字体发现），不复制其代码与其主题/图标体系。
- 本插件内可复用：`file_cache.is_safe_url`（SSRF 校验）、`CacheManager` 的目录与清理思路。
- 已实测：两种搜索源均返回 `trans_param.union_cover`（概念版 `trans_param` 为对象）；`https://imge.kugou.com/stdmusic/240/...` 返回 200 `image/jpeg`。概念版接口对无凭据请求可能不稳定（实测偶发返回空 `info`），不影响本设计，因为封面取自同一响应。
- 本地路径图片的投递方式已确认：AstrBot 的 aiocqhttp 适配器会把 `Image` 段 base64 编码后发送（`image_result` 对非 `http` 字符串走 `file_image`），因此把卡片写到插件数据目录、即使 OneBot 实现端在另一台主机也成立。相关实现位于插件声明的 `astrbot_version >= 4.17.0` 范围内，无需上调版本下限。
- 图片卡片在部分 OneBot 实现上的到达效果与压缩策略取决于实现端，非本插件可控。
