# 酷狗概念版歌曲文件发送改造设计

日期：2026-11-13
状态：待用户确认；本文仅设计，不授权实现、提交或推送。

## 1. 目标与已确认需求

将现有 AstrBot 音乐分享插件改造成歌曲文件发送插件：

- 仅保留酷狗音乐概念版（Lite），删除标准版分支与版本切换开关。
- 仅支持 `aiocqhttp`（OneBot v11），删除 `qq_official` 平台声明与兼容逻辑。
- 最终发送歌曲文件附件，不发送音乐卡片、语音、封面或播放直链。
- 在插件配置中设置有序的音质优先级，默认 `Hi-Res → FLAC → 高品 → 标准`。
- 增加“共享缓存目录”，由用户手动指定；AstrBot 与 OneBot 实现端均能访问该目录。
- 精简原有代码，但保留实现以上功能必需的登录、搜索与凭据管理能力。

## 2. 本设计采用的默认决定

以下是设计者的建议，不是用户额外提出的要求，用户确认本文后实施：

- 沿用先搜歌、再按编号选择的交互。新增 `/酷狗下载 <序号>` 为主要文件发送命令，保留 `/酷狗点歌 <序号>` 为兼容入口；两个入口行为完全相同，均发送文件。
- 保留 `/酷狗搜歌`、管理员扫码登录、微信登录、退出登录与登录状态命令。
- 群内调用发送到当前群的群文件；私聊调用发送到当前私聊。不会额外转发给其他人或其他群。
- 原始音频不转码，不改写标签；文件名称为 `歌手 - 歌名 [实际音质].扩展名`。扩展名以实际音频格式为准。
- 共享目录要求在两个进程中使用相同的绝对路径；本次不实现 Docker 挂载路径映射配置。
- 搜索缓存按会话和发起用户隔离，避免群内其他人的搜索覆盖自己的选择，有效期继续为 5 分钟。
- 管理员登录的酷狗账号仍由插件共享使用，不增加每个用户独立账号体系。
- 缓存保留 1 小时；单次下载上限 200 MiB、超时 180 秒、最多 2 个并发下载。上述为内部安全默认值，不为每个默认值新增配置，后续确有需要再扩展。

## 3. 用户交互

1. 用户发送 `/酷狗搜歌 <关键词>`，收到编号、歌名、歌手、时长等文本结果。
2. 用户发送 `/酷狗下载 <序号>`（或兼容命令 `/酷狗点歌 <序号>`）。
3. 插件检查共享目录、会话缓存、序号和登录凭据，报告正在获取歌曲文件。
4. 按配置音质顺序寻找可用的完整原始音频，下载并验证。
5. 调用 OneBot 群文件或私聊文件上传 API，发送实际文件附件。
6. 上传请求失败时返回明确错误，不伪装成功、不转换为听歌输出。返回成功仅表示 OneBot 上传 API 确认接受，不声称已经验证用户客户端收到文件。

不增加直接歌名下载、批量下载、歌单、歌词、自动续费、账号权限绕过、DRM 解密或其他无关功能。

## 4. 配置

保留 `kugou_cookie`、`kugou_ua`、`search_count`、`timeout` 与 `debug`（实现中可精简其表现，但不输出凭据、签名或敏感直链）。

新增：

### quality_priority（音质优先级）

- 有序字符串列表，默认 `["hires", "flac", "320", "128"]`。
- WebUI 说明各项分别代表 Hi-Res、FLAC 无损、高品 320 kbps MP3、标准 128 kbps MP3。
- 支持调整顺序、删除不需要的档位；去除重复项但保持顺序。
- 非法值、空列表明确提示配置错误，不静默追加用户未选择的档位。
- `hi-ris` 属于需求中的 Hi-Res 拼写，内部统一使用 `hires`，界面显示 `Hi-Res`。

### shared_cache_dir（共享缓存目录）

- 文本路径，默认空，必须由管理员明确填写。
- 要求绝对路径、可创建和写入，且 OneBot 端可从同一路径读取。
- 为空或非法时，搜歌和登录仍可使用；下载命令提示配置问题，不触发音乐下载。
- 不自行启动 HTTP 文件服务，不上传到第三方中转服务。

删除 `kugou_concept`、`card_jump`、`music_card_key`、`card_format`；同步清除过时描述与配置提示。

## 5. Lite 搜索、音质解析与授权

- 固定使用概念版的 appid、clientver、签名盐及登录参数；合并原先 standard/lite 的辅助函数和常量，不保留失效的开关方法。
- 搜索与歌曲解析直接请求酷狗接口，不引入第三方歌曲解析或签名服务。
- 优先使用概念版搜索接口及其质量资源信息；公共搜索作为兼容来源时不恢复标准版账号协议。
- 不能再把所有播放解析固定到 `quality=128`，也不能因封面接口失败而完全跳过文件解析。
- 返回信息应包含可用 URL、实际格式/质量证据、资源 hash、文件大小和时长（以服务端实际可提供字段为准）。
- 仅处理账号正常权限范围内可获得的完整、非加密音频。服务端拒绝权限、要求验证时给出可行动提示，不绕过验证或权限。试听片段不可当作完整歌曲发送。

### 音质优先与降级

按配置顺序逐项处理，不能为了复用低音质缓存而提前跳过高档位：

1. 检查本档位已验证缓存。
2. 缓存不存在则解析本档位可用资源。
3. 资源不存在、无权限、返回低于目标的音质、格式不支持、加密或损坏时尝试下一档位。
4. 同一资源有多个 CDN 地址时可以有限重试备用地址；全局网络异常、目录错误、配置错误不应伪装成音质不可用。
5. 下载成功后只上传一次；上传失败不自动改换音质再次发送，以免错误重试或重复文件。
6. 所有用户配置的档位都不可用则返回原因摘要，不另外请求未配置档位。

### Hi-Res 实现约束

现有源码只实现 128 kbps。上游 KuGouMusicApi 文档确认 `128`、`320`、`flac`、`high` 等参数，但没有确认 `quality=hires`；`high` 描述为无损，不能直接等同于 Hi-Res。

因此实现前需确认概念版接口/质量资源 hash 的 Hi-Res 选择方式，将协议参数与配置标识分开管理。不得为了“支持”而盲目请求 `hires` 或将 `high` 的任何返回直接标成 Hi-Res。

下载后依据音频头和可用响应元数据验证档位：FLAC 的 STREAMINFO 提供采样率、位深、样本数；高分辨率无损的判定为位深 > 16 或采样率 > 48000 Hz，普通 CD 规格 FLAC 不标记 Hi-Res。此验证仅确认编码规格，不声称证明母带品质。MP3 解析码率与音频结构，不能只看 URL 后缀或 Content-Type。

若无法通过公开协议材料确认 Hi-Res 资源选择，实现必须保留优先级语义、明确报告该档位尚不能取得，再按配置降级；不得在交付说明中声称 Hi-Res 已实测可用。没有用户授权的凭据不得执行真实账号登录或下载/群文件发送测试。

## 6. 下载缓存与文件安全

- 所有音频数据放在共享目录下插件专属子目录 `astrbot_plugin_kugou_music/`，每次任务使用独立目录和 `.part` 文件；验证成功后原子重命名为最终文件。
- 凭据与搜索状态继续放在 AstrBot 插件数据目录，不把 Cookie 放在共享音频目录。
- 文件名过滤路径分隔符、控制字符、Windows 非法字符、保留名称与超长字符，绝不使用歌名决定目录路径。
- 音频 URL 必须来自酷狗资源解析，仅接受 HTTP(S)，拒绝内网、环回、保留 IP、URL 中的凭据和未知来源；重定向也需要检查。下载请求不向 CDN 转发酷狗 Cookie/token。
- 流式写入，限制响应大小、下载总时间，校验非空、传输长度和真实音频头；拒绝 HTML/JSON 错误页及加密数据，不把它们命名为音频发送。
- 并发任务互不覆盖。缓存键包含资源标识与实际质量；同一资源下载可复用/合并，但每位用户的上传独立。
- 下载失败、取消时删除当前任务半成品。
- 最终文件在上传 API 返回后继续保留 1 小时，供 OneBot 读取或延迟处理。上传过程中及活跃任务持有的文件不得被清理。
- 初始化及运行期间进行有界清理，只清理插件创建并记录的过期缓存，不递归删除共享目录其他内容，不跟随外部目录符号链接。
- 在本地缓存目录设置内部归属标记/manifest（无凭据），对没有标记的现有目录拒绝自动清理；具体轻量实现交给开发者。

## 7. OneBot 文件发送

- 群聊调用 `upload_group_file(group_id, file, name)`；私聊调用 `upload_private_file(user_id, file, name)`。
- 使用已验证文件的绝对本地路径，并保留用户可见文件名。
- 群/用户 ID 根据 OneBot API 所需类型转换，使用 event 原始上下文对应的当前目标。
- 同时处理 API 抛出的异常和字典中的非零 `retcode` / `status=failed`。
- 未支持文件上传的 OneBot 实现、文件权限/路径错误、文件大小限制、超时等返回明确错误，不报告“发送成功”。
- 停止已处理命令的事件传播，避免后续处理器再次回复。
- 元数据只声明 `aiocqhttp`；文档说明 OneBot 实现需支持群/私聊文件上传扩展 API，且共享目录使用同一路径。NapCat/CQHTTP 的实现差异以真实端到端验证为准。

## 8. 登录保留与精简

- 保留概念版扫码和微信登录的必要签名/加密代码，删去标准版 RSA/微信参数及所有模式选择分支。
- 退出登录只清除插件管理的凭据；登录状态隐藏完整 token，并准确展示扫码/微信/手动配置来源。
- 旧数据文件不被删除；显式 `a_id`/appid 为标准版的 Cookie 拒绝用于 Lite，提示重新登录。没有版本字段的手动凭据不盲目标为概念版有效，依据正常接口授权结果处理。
- 明确区分“已保存凭据”和“在线有效”，不把本地存在 Cookie 当作会员验证。
- 凭据保存失败必须在结果中体现。
- 正确跟踪登录轮询/撤回任务，卸载时取消并等待任务，关闭 HTTP session，避免精简后留下后台任务泄漏。

## 9. 代码组织和精简范围

彻底删除音乐卡片构造、OIAPI/咸鱼签名、卡片发送、封面输出与跳转地址逻辑，删除标准版与 QQ 官方适配说明。

建议使用三个职责清晰的模块而非将新逻辑堆进已有约 1584 行文件：

- `main.py`：AstrBot 命令、配置、概念版登录、生命周期、OneBot 上传协调。
- `kugou_client.py`：Lite 签名、搜索与多质量原始音频解析（与登录复用必要辅助函数）。
- `file_cache.py`：安全路径、受限下载、音频头验证、缓存复用与清理。

模块最终划分、复用方式和轻量音频解析实现由开发者决定；不加入大而全的音乐 SDK、ffmpeg 或第三方解析服务。现有 `aiohttp`/`pycryptodome` 继续使用；必要时采用小型音频元信息库，但必须说明新增依赖和理由。

## 10. 验证与交付标准

使用离线测试和 mock 网络/OneBot API，覆盖：

- 配置优先级、无效配置、共享目录校验与危险文件名。
- Hi-Res/FLAC/320/128 顺序与缺失/无权限/伪高音质时降级；不越过配置列表。
- 音频头识别、位深与采样率、HTML/JSON/加密/试听拒绝及真实扩展名。
- 流式下载、长度/大小限制、失败与取消清理、并发隔离、缓存过期与活跃文件保护。
- 群/私聊文件上传的参数、非零 retcode/failed status/异常；失败不改发卡片、语音或链接。
- 搜索会话用户隔离、序号检查与旧 `/酷狗点歌` 兼容入口。
- 概念版登录参数、Cookie 类型/持久化、敏感日志脱敏、卸载任务清理。
- 配置/README/metadata 一致，仅保留 Lite 与 aiocqhttp，无音乐卡片配置。

运行语法检查与离线测试，更新 README、配置 schema、metadata（建议新版本 2.0.0，以体现不兼容功能变更）。真实账号与 OneBot 测试仅在用户明确授权后开展，并分别报告下载验证与附件到达情况。没有真实环境测试时，明确列为待验证，不用 mock 成功代替接口可用结论。
